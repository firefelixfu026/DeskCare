# 05｜隐私、安全、医学边界与课程应用

> UI17：仅改变选择控件及利用已有提醒回应码，不新增采样、健康数据、文件读取或后台上传。推迟与跳过不假称用户明确否定时机；反馈建议仍独立默认关闭，演示不参与。主动 AI 的分项计数仍逐次预览确认，不发送原始反馈历史或推断不适。桌面提醒仍可关闭、可跳过、不抢焦点。

> UI16 只拆分本次主动选择清单里已有的地点，不新增后台定位、地图请求、文件访问或上传许可。联网正文不追加已有任务库或用户在预览中写的个人备注；仍逐次预览确认，API Key 不在正文中。地点属于用户资料，预览及测试不使用或输出真实用户地点；确认后仅存既有本机 notes，不新增日志或云历史。

## 1. 这是什么、不是什么

DeskCare 是普通人的**数字健康习惯辅助工具**，不是医疗器械、数字疗法、疾病诊断或精神状态判断工具。它可以协助减少无意义的通知干扰、回顾电脑使用与任务安排，不提供医疗诊断或治疗建议。

- 不要声称检测到眼疲劳、情绪障碍、睡眠质量、姿势异常或疾病风险。
- 不要用电脑操作时长评价人的价值、努力程度、身体好坏或道德品质。
- 不应强迫用户休息、限制健康正常的自主选择，不应减少睡眠以赶任务。
- “今天使用时间较长”可以是一个事实估计，但“所以你身体不好”不是有效推论。

## 2. 独立许可与具体数据边界

| 数据范围 | 默认 | 为什么收集 | 存什么 | 不能收什么 |
|---|---|---|---|---|
| 基本设置 | 允许本地保存 | 软件运行 | 通知方式、阈值 | 与功能无关的系统资料 |
| 活动使用时间 | **关闭，需同意** | 展示时长与辅助提醒 | 按日类别活跃秒数、部分提醒上下文 | 键入文字、按键内容、截图、窗口标题、网页 URL |
| 具体应用名 | **关闭，另行同意** | 按应用查看时长 | 规范化应用名/ID 与日汇总 | 进程完整路径、命令行、文档名 |
| 今日任务 | 仅用户主动创建/导入 | 任务管理与联动 | 用户确认的标题/时间/状态 | 任意后台读取未选择的文件 |
| BodyLog 健康感受 | **关闭，另行同意** | 自我回顾（可选） | 用户自报的粗粒度感受 | 系统推断的病症或病历 |
| 本地 AI | **关闭，可选** | 任务候选提取、报告润色 | 用户选择提供的文本/事实（本机推理） | 任何未经选择的后台信息 |
| 云端 AI | **关闭，可选（M9）** | 只解析用户主动选择并逐次确认发送的任务清单 | 单独授权 + 每次发送前完整预览；API Key 使用 Windows Credential Manager | 活动/应用统计、BodyLog、报告以及未经确认的任务文本 |

**权利保护**：提供暂停、彻底停止、数据导出、分类清空和全部清空。删除按钮应显示将删除什么，敏感数据不出现在日志中。程序没有帐号，默认没有遥测和行为上报。

对本地数据库，如果 SQLite 采用 WAL/journal，简单 `DELETE` 不等于不可恢复的数据擦除。不要在 UI 中宣称法证级永久擦除；实现 `DELETE` + `VACUUM` / 关闭连接后删除文件等适当方案，并在 README 中如实说明系统备份残留可能性。

## 3. 安全工程要求

- `csv` 和文本解析必须限制文件大小和每行长度；不执行清单内容里的脚本、链接、Office 宏或公式。输出 CSV 时，若将来支持导出原始任务文本，应处理电子表格公式注入风险。
- 用系统文件选择对话框，**仅读用户选择的文件**；只在用户确认后保存结构化任务；不要把源文件全文保存为调试日志。
- 以类型化对象传输数据，SQLite 使用参数化查询；迁移前备份，开发日志不要输出个人任务标题与打卡内容。
- 线程模型：Win32 采样与重计算不应阻塞 Qt UI；尽量通过 Qt 信号/定时调度；UI 更新在主线程。
- `QSystemTrayIcon` 若不可用，要有明确可退出的可见窗口；监测状态要与后台服务状态一致。
- 自动启动和网络调用都要求显式用户启用。版本升级不偷偷改变授权开关。

## 4. 若进行用户测试

- 仅邀请**愿意自愿参与**的测试者；事先说明收集范围、保留时间、退出办法。
- 尽量让数据完全留在他们的电脑上；如果要分享反馈，优先使用汇总指标或匿名的测试记录，不要索要同学的实际健康记录和应用清单。
- 不展示个人真实任务、健康情况、应用日志截图作公开路演素材，除非获得充分授权。演示优先使用包内虚构样例。
- 测试人数不足时如实表述“可用性探索”，不说“科学证明提高效率/健康水平”。

## 5. 医工交叉课程对应点（供后续大作业）

| 教学目标 | DeskCare 可呈现内容 |
|---|---|
| 人工智能辅助医学实际问题 | 数字健康与人体工效学场景下的低打扰健康行为支持 |
| 人机协作原则 | 活动只是线索、用户自报与确认是关键输入，随时暂停/拒绝 |
| AI/Agent 工作流 | 任务解析（可选模型）→状态聚合→策略决策→反馈→报告 |
| 模型训练与公开基准 | 后续比较规则策略与轻量反馈分类器；用模拟数据做重复验证、真实授权样本做探索性评价 |
| 医学数据隐私与伦理 | 可撤回的独立许可、最小化采样、健康自报不外传、数据清除 |
| 完整医学 AI 案例 | 数据来源说明、流程架构、可测评价、局限性和伦理分析 |

**需要与老师另行确认**：是否必须亲自训练/微调模型、是否要求使用公开医学数据集、能否将数字健康行为支持视作合格“AI+医学”自选课题。赛道可选题与课程最终评分是两个独立判断。

## 6. 后续实验的评价方案（不夸大）

- **对照条件 A**：固定间隔柔性提醒。
- **条件 B**：同样提醒样式，但结合用户选择的情境模式、确认任务的时间约束和自然间隙。
- **主要结果**：提醒被标记“不合适”比例、提醒接受比例、休息确认次数、用户主观打扰评分。
- **重要护栏**：如 B 几乎不提示，不能因为“不合时宜率低”就认定更好。
- **方法**：先用重复模拟情境跑确定性测试；若做真人体验，取得知情同意，尽量避免健康个人信息外发，样本小只能报告观察趋势，不能推断疗效。
- **结论表达**：测得使用体验不代表医学有效性；需要更专业的研究才能证明真实健康效益。

## UI10 新增授权边界

经用户确认，本机不适事件与后续补记新增独立 `health_journal` 许可，默认关闭，允许随时取消、选定导出和删除。旧每日打卡不迁移为症状事件；身体部位、程度、时长、备注均可省略。只显示本人填写内容，不训练模型或做医疗结论。开启前说明本地数据库不加密、不向 AI 发送及撤回删除范围。

新增健康内容不进入原日报／周报模型事实表或云端任务 payload。用户确认的普通行动任务与记录关联；清空／撤回不适记录保留普通任务，全部清除才包括任务。导出文件和外部备份需用户自行保管，旧版无法管理新表，回退前必须用新版清理。下一阶段医院检验资料需另外明确权限与保护，不得沿用本次许可自动上传。

## UI11 经用户要求新增的主动提醒情境分析

新增 `reminder_context_ai` 独立许可（默认关闭），不复用云端任务许可，也不改变 UI10 健康历史不外发的边界。只有用户主动预览并逐次确认，才能把选定任务、当前模式、当前累计活跃估计、反馈计数、可选本次粗粒度感受发给所选本机／联网服务。开启许可本身不联网，未选感受默认不提供；不自动读取历史打卡、不适事件、检验单、应用名称或活动轨迹。暂停／关闭电脑统计时本链路不发请求。

选择联网时，界面显示目标、模型和完整请求正文，说明任务／感受会离开本机及可能收费／被服务商留存；用户可不提供感受、不选任务或取消发送。结果不能给医疗结论。内容仅在内存，不记录到日志／新历史表；撤回授权和全部清除使迟到结果失效，但已发送请求无法撤回。沿用 Windows 凭据管理器认证，密钥不进入预览正文。后续医院资料处理仍需单独阶段、具体资料和许可，不能借本权限自动读取或上传。

## UI12 助手许可与易读确认

新增默认关闭的 `assistant_tools_ai`，不继承其他许可。每次仅发送用户这次主动输入、当前提醒间隔／情境及本机时间，先以普通文字核对并确认；提醒分析也改成逐项可读清单，不要求用户理解 JSON。助手不读取或自动上传聊天历史、任务库、活动／应用轨迹、健康记录、屏幕或工具结果。工具读取仅在本机显示，写入须再次确认；无健康、检验单、任意命令／文件工具。聊天只在窗口内存保留并限长，关闭清空。手动任务／设置操作不依赖活动采集许可，不因此开启监测；撤回、清空及取消使旧提议失效，已发送网络内容不能收回。原本机健康历史隔离不变。
> UI13 隐私增量：`lab_reading` 与 `lab_reading_ai` 分别默认关闭，不继承助手、任务、打卡或不适许可。用户主动选原件，本机逐页处理；AI 每次只发核对后可明确对照的指标，不发原件、全文、身份或历史。指标本身仍敏感，并非保证匿名；联网可能收费／被留存。关闭清空应用持有的本次内容、不改原件；扫描临时 PNG 正常清理，不能保证崩溃清理或取证级擦除，已发送内容不可撤回。范围对照与一般知识不替代诊疗，来源见 UI13 说明。
> UI14 不增加权限或健康字段。旧版归档仅选择项目 dist/release 的旧产物，不上传 build／测试数据库、真实个人数据或密钥。公共 CA 证书与私钥明确区分；源代码与 Git 不在删除列表。服务端哈希一致并有已验证新版后才删，文件改动或锁定时保留，旧版可从 GitHub 恢复，不承诺取证级擦除。

> UI15 去重只在用户主动导入流程中本机读取已有结构化任务，不额外上传任务库、备注或健康历史。联网正文仍限本次选定清单、逐次确认；开启、预览、比对不触发请求。草稿及比对不写调试日志，取消无任务写入，不借此批量删除或修改旧任务。

## UI18 经用户明确授权的数量汇总复盘

本轮用户选择接入已配置的联网 AI。新增独立、默认关闭的 `report_review_ai`（也用于本机复盘），不继承任务、提醒、助手或健康许可。仅在本次中文预览和确认后发送报告日期范围、演示标记、覆盖天数、活动／空闲／未知分钟总量、任务数量、提醒各项计数与这些数量生成的候选卡片。不开启后台发送，不读取密钥用于预览。复用 Windows 凭据认证，但凭据不在正文。

这是此前“报告、活动统计不发云端”条目的狭窄、用户主动例外；完整日报、应用名／类别、小时或原始轨迹、任务名称／备注、打卡／不适／检验资料仍不在该链路。数据在窗口内存，不新增 AI 历史、请求日志或健康表。可随时撤回；关闭、主动刷新、切换报告、全部清除、内容／服务／授权变化及五分钟过期使旧请求或结果失效。已发送内容无法撤回，可能产生费用或被服务商保留。既有其他 AI 链路的具体许可不改变，健康历史隔离仍然保留。
