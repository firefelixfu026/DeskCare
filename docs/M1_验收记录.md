# DeskCare 2.0｜M1 验收记录

## 本轮范围

- 受控 Windows provider：读取键鼠空闲秒数，并将前台进程归入 `CODE / BROWSER / MEETING / OFFICE / OTHER / UNKNOWN` 粗粒度类别。
- 只有活动监测明确开启且未暂停时才允许 provider 读取。
- 以 `monotonic` 间隔估算活动、空闲、未知时段；超过 60 秒的采样间隔丢弃，避免把锁屏、睡眠或调度停顿当作持续活动。
- SQLite v1 增量迁移：`schema_migrations`、`consents`、`usage_daily`。
- 使用统计页展示当日活动估计、类别汇总、空闲/未知时段和采样边界说明。
- 维护当前连续活跃会话估计；空闲、未知、暂停、异常和长间隔都会截断会话。
- 支持显式 `--demo` 模式，使用标记清晰的 FakeProvider 进行离线演示，不改变默认授权门控。
- 设置页提供带二次确认的活动统计清除入口，清除数据不改变授权状态。

## 自动化验证

在 Python 3.12 环境执行：

```powershell
python -m compileall -q deskcare tests
python -m pytest --basetemp .pytest-work -q
```

结果：16 项测试通过。

覆盖内容：未授权不采样、暂停后不采样、暂停立即截断会话、provider 异常降级、FakeProvider、显式 demo provider、四页 UI、SQLite 迁移和参数化聚合写入、活动数据清除后授权保留、清除后的 UI 刷新通知、跨午夜分桶、长间隔丢弃、空闲时段记录、连续活跃会话、Windows tick 回绕处理和类别映射隐私边界。

## 隐私边界

- 不读取键盘内容、窗口标题、网页 URL、剪贴板、截图、摄像头、麦克风或文件内容。
- 具体应用名统计默认关闭；provider 只在内存中把可访问的进程路径映射为粗粒度类别，不保存原始路径或应用名。
- 不上传数据，不调用 LLM，不进行疲劳、视力、睡眠或疾病判断。
- 未开启监测时，统计页显示“未开启/暂无数据”，不伪造 0 分钟。
