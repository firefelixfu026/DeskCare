## 1. 约束和架构原则

**运行时** Windows 10/11 x64；Python 3.11/3.12；PySide6 Qt Widgets；`ctypes`/必要时 `psutil`（仅读当前前台进程，不能遍历无关文件）；SQLite `sqlite3`；pytest；PyInstaller（需在 Windows 构建）。

- **本地优先**：不需要账号、后端、联网或 API key，即可完成核心闭环。
- **分层、可测**：系统采集、任务解析、政策/策略决策、报告引擎、SQLite、Qt UI 相互解耦。
- **用户主导**：不对未确认的 AI 识别输出作确定性写入；重要配置和导入结果必须可编辑。
- **单实例运行**：避免重复启动后记录两份数据。实现可在 M5 完善，但应先防止重复采样。
- **迁移友好**：如果旧 DeskCare v1 仓库存在，保留已有 provider、policy、repository 的有效实现，添加模块和数据库迁移。

## 2. 业务领域模型（契约）

```python
from dataclasses import dataclass
from datetime import datetime, date
from enum import Enum
from typing import Protocol

class ActivityKind(str, Enum):
    ACTIVE = "active"
    IDLE = "idle"
    UNKNOWN = "unknown"

class BreakAction(str, Enum):
    NONE = "none"
    SOFT_NOTIFY = "soft_notify"
    DEFER = "defer"

class TaskStatus(str, Enum):
    TODO = "todo"
    DOING = "doing"
    DONE = "done"

@dataclass(frozen=True)
class ActivitySample:
    monotonic_s: float
    wall_time: datetime
    idle_s: float | None
    app_category: str | None  # CODE / BROWSER / MEETING / OFFICE / OTHER / UNKNOWN
    state: ActivityKind
    is_foreground_change: bool
    observation_ok: bool

@dataclass(frozen=True)
class TaskDraft:
    title: str
    due_at: datetime | None
    estimated_minutes: int | None
    source_row: int | None
    uncertainty: tuple[str, ...]  # 例如 "due_time_ambiguous"

@dataclass(frozen=True)
class PolicyContext:
    monitored: bool
    mode: str  # normal / focus / meeting / reading / quiet
    continuous_active_minutes: float
    idle_seconds: float | None
    is_recent_switch: bool
    next_confirmed_deadline: datetime | None
    now: datetime
    last_prompt_at: datetime | None
    last_response: str | None
    manual_pause: bool

@dataclass(frozen=True)
class PolicyDecision:
    action: BreakAction
    reason_codes: tuple[str, ...]
    human_explanation: str
    next_check_in_seconds: int

class ActivityProvider(Protocol):
    def read_sample(self) -> ActivitySample: ...

class TaskImporter(Protocol):
    def preview(self, content: bytes, filename: str) -> list[TaskDraft]: ...

class BreakPolicy(Protocol):
    def decide(self, context: PolicyContext) -> PolicyDecision: ...
```

其中 `ActivityProvider` 返回对**当前会话有限信息**的估计，不推断人的心理状态。`TaskDraft` 只是一份候选；`Task` 对象需拥有 `confirmed_at`，用户确认才进入决策。对任意不确定截止时间不得悄悄指定日期。

## 3. Windows 采样与会话归并

- `GetLastInputInfo` 获取本会话最后输入 tick；配合单调时间估计 IDLE。**空闲表示最近无键鼠输入，不等于离开、休息、睡眠**。
- `GetForegroundWindow` + `GetWindowThreadProcessId` 获取当前前台程序关联进程；映射**类别**，不读取窗口标题。失败时类别 `UNKNOWN`，不应追踪调用栈或额外探查。
- 默认每 5 s 采样到内存，使用**增量聚合**写入按日类别分钟（建议每 60 s 批量写入），避免逐秒轨迹数据库。
- 检测系统睡眠、锁屏或采样长间隔（如单调间隔超过 60 s）后，应截断/忽略不可观测区间，不能当作一直在工作；实机验证 Windows 锁屏事件支持，无法确定时输出 `UNKNOWN`。
- 使用 `time.monotonic()` 测量 elapsed；持久化日界使用系统本地时区 `date`，跨午夜需切桶；数据库时间尽量存 UTC ISO8601 加已知时区/本地日期。
- 仅用户单独选择“按应用统计”时才存程序的**规范化简短标识**（如 `code`, `chrome`），不存全路径/命令行/页面 URL。UI 必须有“关闭此统计，清除已有应用级数据”按钮。
- 统计称为“**电脑活动时间估计**”，不是精确的真实屏幕使用时长。

## 4. 数据库（建议 SQLite v2）

使用 `schema_migrations(version, applied_at)` 维护增量迁移；`CREATE TABLE IF NOT EXISTS` 不应代替正式变更。所有数据写入采用参数化 SQL，使用事务。

| 表名 | 关键字段 | 敏感性 / 说明 |
|---|---|---|
| `consents` | `scope` PK, `granted`, `updated_at` | 活动监测 / 具体应用名 / 健康状态 / 本地 AI 独立同意 |
| `preferences` | `key` PK, `value_json`, `updated_at` | 阈值、静默模式等；数值要验证范围 |
| `usage_daily` | `day`, `category`, `active_seconds`, `unknown_seconds`, `updated_at` | 类别汇总，联合主键 `(day, category)` |
| `app_usage_daily` | `day`, `app_id`, `active_seconds` | 可选单独授权，可整体删除 |
| `task_sources` | `id`, `display_name`, `imported_at`, `parser_name` | 仅文件名简述，不存文件绝对路径或源文件内容 |
| `tasks` | `id`, `title`, `due_at`, `estimated_minutes`, `status`, `confirmed_at`, `completed_at`, `source_id`, `created_at` | 任务内容较敏感，尽量少存原始文件文本 |
| `reminder_events` | `id`, `occurred_at`, `decision`, `reason_codes_json`, `mode`, `active_minutes`, `response`, `response_at` | 保留解释依据，但不保留窗口标题 |
| `wellness_entries` | `id`, `day`, `eye_comfort`, `body_comfort`, `note`, `created_at` | **默认关闭**、须单独授权，备注可完全不采集 |
| `reports` | `id`, `period_type`, `start_day`, `end_day`, `body_text`, `fact_snapshot_json`, `generated_at`, `generator` | 报告可重建，来源范围可见；健康信息按许可处理 |

**最小数据保留**：建议活动类别汇总默认保留 30 天（用户可延长/缩短），应用级统计和健康自报不自动上传；报告可单独清除；用户删除全部数据时应清空相应 DB 表，必要时重建数据库。SQLite journal/WAL 等残留处理需要真实验证：不能声称“无法恢复地彻底擦除”。

## 5. 数据流与跨模块契约

```text
User-selected files ─▶ Importer ─▶ Draft Preview ─[user confirm]─▶ Task Repo ─┐
                                                                            │
Win32 Provider ─▶ Activity Aggregator ─▶ Usage Repo ─▶ Activity Context ─────┼─▶ Policy Engine
                                                                            │       │
User Context Modes / Settings ────────────────────────────────────────────────┘       └─▶ Reminder UI
                                                                                      │
                                                          Confirmed action / feedback ─┘
                                                                                      │
Task Repo + Usage Repo + Reminders + Optional Wellness ─▶ Report Facts ─▶ Template/Optional LLM
```

- **任务标题不等于活动事实**：检测到 IDE 活跃不能自动标记“ADS 编程题已做完”，至多提示用户确认任务。
- **健康状态不等于电脑推断**：不能根据持续使用推断“今天眼睛疲劳 8/10”；没有打卡就显示“未记录”。
- **没有 AI 服务时**：导入可用确定性格式解析；报告可用模板直接生成；策略纯规则运行。

## 6. 任务文件解析规范

- 输入：`.txt`（每行任务）、`.md`（`- [ ]` / `- [x]` / 列表项）、`.csv` 或 `.xlsx`（`title,due_at,estimated_minutes`）。XLSX 仅读取第一个工作表的值，不执行公式；输入路径仅由系统文件选择器提供。
- `.csv` 使用 `csv.DictReader`，列名大小写和空格宽容处理，禁止公式执行；对每行限制长度；超大文件给错误而非卡死；先读内存，**预览后保存结构化 Task**。
- 自然语言日期如“明天下午”“周三”可能含歧义，P0 不推测具体时间；保留任务标题，截止时间为空，并在预览提示编辑。若日期有完整 ISO 字符串可解析，清楚处理本地时区。
- `md` 的 `[x]` 可以标记文件文本中的勾选状态，但**仍需用户确认**，不得自动将其作为真实已完成活动的证据。
- XLSX 工作簿按压缩文件大小、总解压大小、成员数、单 XML 大小、行数和列数做限制；拒绝外部工作表链接、公式单元格、DTD/实体声明和加密工作簿。
- 所有文件解析不能自动执行宏、JS、公式或外部链接；文件最大 2MB（可配置），对异常编码和空文件友好报错。

## 7. AI 模块接口

```python
class TaskParseAssistant(Protocol):
    def suggest(self, text: str) -> list[TaskDraft]: ...  # 用户确认前不持久化

class ReportNarrator(Protocol):
    def narrate(self, fact_sheet: dict) -> str: ...      # 只基于事实，输出仍需校验
```

P0 默认 `HeuristicTaskParser` 和 `TemplateReportNarrator`。可选本地模型适配器单独模块，接口与输出使用 JSON schema / pydantic 校验；模型挂掉、超时、未安装即降级，**不能阻塞软件**。M9 云端模型仅限用户主动选择的任务解析，云端授权独立且默认关闭；每次请求先展示准确 JSON 正文并逐次确认；API Key 只能进入 Windows Credential Manager。活动、应用统计、BodyLog 和报告不得隐式加入 payload。

## 8. 时间、异常与迁移

- 事件用稳定 ID，必要时 UTC ISO8601；`today` 等按本地日期计算，跨天更新策略。
- 修改系统时间、睡眠唤醒、程序崩溃、断电时不把不可观测时长补齐成活动时长。
- 首次无监测授权：所有页面可进入但统计显示“未开启”，不填假数据。
- 同一数据导入多次：提供去重预览，不默默删除任务。
- 旧版数据库在变更前备份一次可恢复副本（不包含敏感数据在日志里），用迁移脚本添加表，不丢现有数据。
- 打包先测试 PyInstaller `onedir`，再视需要做 `onefile`；不得用 Linux 构建结果宣称 Windows exe 有效。

## 9. UI10 本机记录的增量契约

SQLite v9 增加 `health_events`、`health_followups`、`health_action_links`，由 `storage/health_journal.py` 与 `services/health_journal_service.py` 管理；授权 scope 为 `health_journal`，不继承 `wellness_checkin`。发生时间和补记时间为用户确认的本机民用时间；描述必填，其余身体部位、程度、持续分钟及备注可省略，不预填症状。补记不早于发生时间，未来事件不当作已发生记录。

行动写入必须有显式确认，任务与关联同一事务写入，取消不写。默认只复制用户在行动表单确认的普通任务字段，不复制不适描述；删除事件级联删补记／关联，保留已确认任务；删除任务只将关联 task_id 置空。外键启用，写入／删除原子性有测试。TaskService 统一通知刷新既有任务和提醒消费者。

新增记录不进入 ReportFactsBuilder、LocalAIService 或 CloudTaskAssistant；回顾和 TXT 导出走独立纯本机通道。撤回授权删除事件／补记／关联，全部清除也覆盖新增表及受管理 `.before-ui10` 备份。升级备份不自动加密，不承诺外部副本擦除；回退旧版前须用新版清理新增数据。

## UI11 独立提醒分析契约

ReminderAdviceService 捕获不可变快照：明确模式、计时估计、选定已确认任务、经许可的反馈计数、可选本次感受；不读取 UI10 健康表、历史打卡、任务备注、应用轨迹。ReminderAIAdvisor 独立于 CloudTaskAssistant，复用已有服务配置及凭据保存设施，但不继承任务上传许可；新增 `reminder_context_ai` 默认关闭，逐次准确正文预览确认。UI 的工作线程仅执行本次请求，模型返回限定 action／evidence／interval_minutes，校验后仍是建议，不进入自动策略。状态／授权／配置变更和超时快照失效；确认采纳后经 ReminderCoordinator.set_interval 保存，硬门控不变。无新数据表，分析内容不持久化；旧 AI 通道不接收健康历史。

## UI12 工具助手及同步

AssistantService 单次准备消息／当前提醒设置 → 独立许可与人类可读核对 → 模型规划一个白名单工具 → 参数／意图校验 → 本机只读执行或用户确认写入。ToolPlan 有请求身份、授权版本、时间和预期设置，单次消费，取消／过期不能重放。读取结果不进入下次模型请求，无聊天持久表。structured_transport 共用受限 JSON 传输，业务执行只在 UI 主线程走既有服务。协调器每次通知同步实际间隔和情境控件，仅权威值改变才更新输入，避免覆写未提交草稿。AI 候选不再从 1 分钟比例生成；任务 ID 只在本机用于失效校验。详见 UI12 说明。
> UI13 数据契约：`domain/lab_reading.py` 不含通用医学阈值；QtPdf 与固定 PowerShell Windows OCR 只读取主动选择的一页。`LabReadingService` 仅内存草稿，独立本机／AI 许可，修订号与请求单次令牌防重放／迟到覆盖。AI 接收经核对且可明确对照的最小指标集，只返回允许的指标／问题编号，不输出任意临床文字。无新健康表，不混入任务或日报模型事实。详见 `UI13_检验单辅助阅读.md`。
> UI14：复用 tasks.completed_at／planned_for／starts_at／ends_at，无表迁移；TaskService 统一未完成／后续／完成查询，完成列表按实际时间倒序，日期缺失独立组。重复标为完成不重写日期；撤销清空完成时间。日期范围不推成预计投入或截止闹钟。归档使用逐字节 SHA256 对象及路径索引，删除独立门控且限定 dist/release 的显式旧版根。

> UI15：domain/task_duplicates 为纯本机草稿比对；标题 NFKC／大小写／空白统一，时间按本机分钟精度及有效安排日比较，包含长期结束时间。新备注／明确预计用时及缺时间标待核对，AI 预计值变化不生成重复。TaskService.confirm_import 使用独立 import_tasks，在 BEGIN IMMEDIATE 事务内重新查询及去重后插入；手动创建契约不变，无表迁移，不更新已有行。

> UI18：ReportReviewService 从 FactSheet 逐字段白名单建立不可变数量快照和候选卡片，不复制全报告再删字段；复用已配置服务、凭据与限时 JSON transport，权限使用独立 `report_review_ai`。请求 token 单次使用、五分钟有效、正文／配置／许可版本绑定，关闭／刷新／清空失效。工作线程经 QObject 绑定的主线程槽更新界面，后台采样不混入旧快照；不写新历史或迁移表。模型仅能选择候选 ID 与对应跳转 action；数字与文案由主机事实渲染。悬浮任务详情只读，确认完成前重查整条任务，变化则不覆盖。
