# DeskCare 项目阶段报告

2026年10月20日 | UI4 | 面向项目负责人及参赛展示

DeskCare 已具备 Windows 本地桌面应用的主要使用流程：整理今日任务、查看经授权的电脑使用估计、按情境接收柔性休息提醒、自主记录状态，以及查看有事实依据的日报和周报。本轮重点修整今日任务列表，并整理当前交付、证据与下一阶段计划。

当前结论是可以继续进行小规模体验测试，但尚不适合宣称正式商用、医学有效或没有 bug。下一阶段应先解决真实使用中的阻塞问题，再验证 AI 整理能力及用户是否愿意持续使用。

## 目前已经实现的功能

### 任务与电脑使用

今日任务支持手工添加、编辑、删除，以及待处理、进行中、已完成三种状态。TXT、Markdown、CSV、XLSX 清单先进入可编辑草稿，只有用户确认后才保存。电脑使用记录不会自动把任务标记为完成，未启用监测也能管理任务。

电脑使用统计在首次启动时关闭。开启后按日汇总活跃、空闲和未知时间，展示近七天柱状图与类别环形图。具体应用名称需要另行授权，关闭该项后清除已有应用级记录。锁屏、休眠和长时间采样中断不能补算成工作时间；这些数字是估计，不代表真实劳动时长。

### 提醒与自我回顾

规则策略会参考用户选择的情境、已确认的任务期限、连续活动估计及提醒反馈。提醒可选择现在休息、稍后提醒、跳过或时机不合适，不强制锁屏或关闭程序。轻活动建议可以关闭。

状态打卡另行授权，选项为无明显不适、有点不适和不想记录，支持删除。日报与周报使用已保存的结构化事实生成，提供本地渲染与导出；缺少记录时说明缺失，不能把电脑使用时间解释为疲劳或效率。

### 桌面伙伴与发布形式

用户可切换简洁面板和吉祥物两种伙伴样式。伙伴支持快捷任务操作和情境选择；吉祥物日常表情跟随用户今天主动保存的状态，另有拖动及左右探头图片。没有记录时只显示未记录占位，不新增状态，也不沿用昨天的记录。

目前吉祥物使用透明 PNG 切换，并非 Live2D。内置录音和语音转文字已经按用户要求移除。程序具备托盘、暂停、退出、单实例以及隔离演示数据；当前以未签名 Windows 便携目录交付。

## 本轮界面调整与测试结果

### 今日任务列表

原来的状态输入框高度与表格行不匹配，形成突出的白色边框。本轮改为嵌入行内的浅色状态标签：待处理用灰绿，进行中用浅琥珀色，完成用浅绿色。文字仍保留，不只依靠颜色区分。

列表移除行号及竖向网格，统一为 56 个逻辑像素的行高，标题列随窗口伸缩；截止时间和预计用时保持对齐，缺失值统一用横线，时长直接带分钟单位。完成的标题弱化显示，长标题提供悬停全文。编辑、删除改为次级按钮，双击任务可进入编辑。

修改状态后会保留该任务的选中身份，避免列表刷新后编辑或删除对象发生错位。没有改动任务数据含义、监测许可和提醒策略。

## AI 能力与隐私边界

### 已有代码能力

本地 AI 适配器可将用户选择的清单交给本机模型，返回候选任务；也可对受约束事实表生成本地报告叙述。云端 AI 适配器只接受用户主动选取并逐次确认发送的任务清单，服务密钥使用 Windows Credential Manager，不进入普通配置、日志或导出文件。

这些能力有接口、输入输出校验、模拟传输与降级测试，但真实模型质量和实际服务商链路尚未完成验收。普通用户仍需自己配置服务；目前还没有免配置的托管 AI 服务。

### 不应夸大的部分

休息时机决策主要是确定性规则，不是训练出来的健康模型。反馈自适应是在样本达到要求后，受限地调整提醒参数，不能宣称已经理解用户身体状况。默认报告是本地事实模板，不应宣传为医疗 AI 报告。

没有模型、网络或 API Key 时，任务管理、授权统计、提醒和模板报告仍应可用。模型失败不得影响这一基本流程。

### 不改变的数据原则

活动统计、应用名称、状态打卡和 AI 权限分别控制，首次默认关闭相关采集。程序不记录键盘输入内容、窗口标题、网页地址、屏幕截图或剪贴板，不在后台扫描用户文档。云端任务整理不携带电脑使用统计、健康打卡或报告。

删除操作按范围确认；本地数据库删除不等于法证级不可恢复擦除，系统备份仍可能存在副本。吉祥物表情只表达用户保存的选项，不据此推断病症。当前项目不提供诊断、治疗或疗效承诺。

## 尚待验证及明确未实现的事项

### 需要优先复验

| 优先级 | 待验证事项 | 通过标准 |

| P0 | 吉祥物左右贴边及恢复 | 两侧均可见探头，悬停恢复，可拖回；跨屏不丢失 |
| P0 | UI4 实际窗口任务操作 | 三种状态不卡顿，长标题不遮挡，编辑对象正确 |

| P1 | 真实 AI 与异常网络 | 正确预览发送内容；超时、断网和坏输出可退回离线流程 |
| P1 | 持续运行与跨天 | 连续八小时、锁屏唤醒及午夜后统计和表情正确 |
| P1 | 普通用户首次体验 | 不讲解代码也能完成添加任务、暂停统计和查看日报 |

UI3 曾在隔离的 Windows 演示实例验证：启动、两种伙伴切换、透明显示、三种自报状态、添加任务及伙伴勾选同步。短距离拖动有位置变化，但左右贴边未可靠确认。右拖后出现过伙伴截图未返回、切换样式后恢复的现象，仍需区分实际可见性问题和测试工具限制。

这些 UI3 实机结果不能替代 UI4 的实机验收。当前离屏自动化不证明多屏、不同系统主题、真实 Win32 采样精度或长时间性能都已通过。

### 尚未实现

真正 Live2D 动画、签名安装包、自动更新、账号和云同步、移动端、普通用户免配置 AI 服务尚未实现。真实用户留存、付费意愿和提醒收益没有研究结论。GitHub 同步此前遇到凭据环境问题，不能把本地交付等同已推送。

吉祥物原图由用户提供，已生成透明副本供应用使用；公开比赛展示及商业使用的授权范围仍应由项目方确认。

## 下一阶段计划与交付位置

### 第一阶段先把现有体验测稳

先完成贴边、键盘输入、长标题、状态修改、托盘退出及干净机验证。每个缺陷保留复现步骤、预期和实际结果，修复后添加回归用例。涉及真实数据删除或新的联网授权时，由用户确认，不为测试擅自开启。

本阶段退出条件是没有已知的启动、数据错写、授权失效或无法退出问题；常用分辨率和 100%、125%、150% 缩放没有遮挡。不能把未复现的间歇问题直接标记为已解决。

### 第二阶段验证 AI 是否确实省事

准备至少 30 份授权的虚构或去标识清单，对照规则解析与真实模型，记录任务遗漏、凭空新增、日期错误、用户修改次数、耗时和失败率。所有结果保持草稿确认，尤其不能擅自补上模糊日期。

若普通用户仍需要复杂配置，再设计服务选择与费用说明。是否提供托管服务应在隐私、成本和需求验证后决定，不在本轮新增后台服务。

### 第三阶段开展自愿体验与商业验证

邀请 10 至 20 名学生及办公用户进行七天探索性试用。先看能否独立完成核心操作，再比较固定间隔与情境提醒的打扰评分、接受比例和提醒覆盖，避免以少提醒制造好看指标。研究不收集参与者原始健康记录或私人任务全文。

同时确认赛事最新要求、素材权利、依赖许可和发布方案。商业计划书中的定价与渠道需通过访谈和真实选择验证后才能变成经营承诺。

### 交付导航

新版启动文件位于项目根目录下 dist/DeskCare-UI4/DeskCare-UI4.exe。旧 UI3、UI2 和更早版本保留，不覆盖；当前仍是便携目录，复制时需带完整文件夹。

本报告的功能和测试依据来自当前源码、自动化输出、PROGRESS.md 及 UI3 实机记录；它不是外部审计或商业营收证明。
