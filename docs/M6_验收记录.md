# M6 验收记录

## 范围

M6 为任务导入和报告增加可选的本地 Local LLM 辅助，并以独立授权提供有限、可解释的提醒反馈个性化。它不改变“用户确认后才入库”的任务边界，也不实现云端调用、健康判断或自动完成任务。

## 已实现

- 设置页新增独立的“本地 AI”授权，默认关闭。
- 仅处理用户主动选择的单个 `.txt`、`.md` 或 `.csv` 文件，不后台扫描文件夹。
- 客户端只接受 `localhost`、`127.0.0.1` 或 `::1` 回环地址；默认兼容 `http://127.0.0.1:11434/api/chat`。
- 通过严格 JSON 契约解析任务标题、截止时间和预计分钟；输出先进入现有预览对话框。
- 只有源文本中原样出现的日期才可被模型候选保留；“明天”“下午”等模糊内容保留为待确认，不静默推断。
- 模型不可用或输出不合格时保留规则解析结果，用户仍可编辑并确认。
- 报告页提供显式“本地 AI 改写”按钮；只把 FactSheet 发送给本机模型，模型返回的文字模板不能直接写入数字，数字由 DeskCare 代入；校验失败回退模板报告。
- SQLite v5 保存 endpoint/model 配置；设置页只做 loopback 和模型名格式校验，不在保存时联网；用户执行全部清除后配置一并删除。
- 设置页提供用户主动触发的本机模型检测；后台只请求回环地址的 `/api/tags`，不发送任务、报告或 BodyLog，并明确显示服务离线、空模型列表、配置匹配/不匹配。
- 报告 AI 请求在 Qt 后台线程执行，按钮有处理中状态；模型失败仍回退模板，不阻塞主窗口。
- 任务草稿 AI 请求也在 Qt 后台线程执行；等待时保留可编辑规则草稿，失败不弹出阻塞式错误，用户取消对话框后丢弃迟到模型结果。
- 不持久化源文件全文、提示词、原始模型响应或绝对路径。
- 提醒反馈个性化默认关闭且独立授权；只读取用户在真实模式下明确提交的提醒反馈，模拟数据被明确排除。
- 至少 10 条总体反馈且当前情境至少 5 条时才评估；只有当前情境“时机不合适”占比达到 40%，才把候选窗口从 40 分钟延后到 45 分钟。不会让提醒更频繁，也不修改任何硬门控。
- 设置页显示样本不足、保持默认或已调整的具体原因；“恢复默认提醒参数”只关闭个性化，不删除反馈历史。

```powershell
python -m compileall -q deskcare tests scripts

python -m pip check
```

当前 E 盘项目 M6 回归为 **64 passed**。其中包含一个仅监听 `127.0.0.1` 的 Ollama-compatible HTTP 协议集成测试；它验证本地通信和 JSON 解析，不代表真实模型质量。新增用例覆盖任务 AI 非阻塞执行、迟到结果丢弃、活动工作线程安全退出，以及个性化授权、样本门槛、按情境隔离、有限调整、暂停硬门控、设置页授权/恢复默认联动和演示数据排除。当前机器没有已安装的可用模型，因此不能宣称真实模型已运行，真实模型仍需按人工清单验证。

Windows 构建补充验证：机器 PATH 同时存在多套 Python 时，最小 PySide6 QtCore 探针可以复现 PyInstaller DLL 导入失败；使用 `scripts/build_windows.ps1` 的隔离 PATH 后探针 `exit=0`。修复版 onedir 与 onefile 均已在 Windows 11 + Python 3.12.7 + PyInstaller 6.22.3 上启动到 `DeskCare` 主窗口并正常退出，无 `Unhandled exception`。Clash 代理开启或代理变量指向不可用端口时，回环 HTTP 集成测试仍通过，客户端不经代理访问本地模型。

交付包回归已固化为 `scripts/verify_windows_package.ps1`：检查 onedir 的 Qt6Core 文件，使用隔离 `LOCALAPPDATA` 启动 `--demo`，要求出现 `DeskCare` 主窗口且不得出现 `Unhandled exception`，最后只停止本轮进程并删除临时数据。现有 onedir 与 onefile 均由该脚本实际验收通过；`build_windows.ps1 -Verify` 可在构建后自动执行同一检查。

补充环境检查：本机已安装 Ollama 0.30.7；本轮短时启动服务后，应用客户端在坏代理变量下对 `GET /api/tags` 返回空元组 `()`，证明回环直连与模型列表解析可用。未自动下载模型，服务进程已停止。含该功能的 onedir 和 onefile 已通过带 `-Verify` 的正式构建流程。

加入反馈个性化和设置页联动测试后，onedir 与 onefile 再次使用带 `-Verify` 的正式流程重建。两个产物均实际启动到 `DeskCare` 主窗口，自动检查未发现 `Unhandled exception`，此前 QtCore DLL 加载故障没有回归。

后台任务 AI 审计曾以独立子进程复现“请求运行中退出”异常；主窗口现统一停止事件循环并等待有界工作线程结束，同一复现脚本以 `exit=0` 干净退出。

包含时区截止时间、短窗口滚动、清除后跨页面一致性及线程退出修复的最终 onedir/onefile 已再次执行正式 `-Verify` 构建，两个包均实际启动到 `DeskCare` 主窗口且无未处理异常；最终 E 盘回归为 64 项全部通过。

## 伦理与安全边界

- 本地 AI 不是医学模型，不接收 BodyLog 内容，也不解释活动或健康状态。
- 本地模型输出始终是建议草稿，不是用户事实；必须人工核对并确认。
- 没有本机模型时，规则解析保持可用，不能将“AI 不可用”显示成任务导入失败。
- 反馈个性化不是健康推断或黑箱模型；样本不足时必须明确保持默认，不能宣称已经学会用户习惯。
- 用户撤回个性化授权后立即恢复默认提醒参数；历史反馈仅保留为用户本地记录，全部数据清除仍会删除它们。
