# DeskCare 产品定位与技术架构

更新日期：2026-10-19。本文描述当前实现与产品假设；不是临床疗效声明，也不是已完成用户研究的结论。

## 给普通用户的一句话

DeskCare 把“今天要做的事”和“电脑前的使用节奏”放在同一个 Windows 小工具里。它可以在你允许后，粗略估计电脑活跃时间；你可以自己选工作情境、决定是否休息、记录简单状态并查看本地小结。不开启电脑统计也能用任务清单。它不是医疗设备，不会判断疾病或替你决定是否工作。

## 与相邻工具的区别（定位假设）

| 工具类别 | 主要解决的问题 | DeskCare 的侧重点 |
| --- | --- | --- |
| 休息提醒工具 | 根据键鼠活跃时间安排微休息、较长休息或每日上限 | DeskCare 不只计时；还把用户确认的任务、情境选择、提醒反馈和可选状态打卡放入同一份本地回顾 |
| 独立待办工具 | 记录任务、期限和完成状态 | DeskCare 保留任务导入预览和手工确认，并把任务完成信号作为提醒策略的一个轻量上下文；不声称理解任务内容或自动判断完成 |
| 习惯/健康追踪工具 | 记录个人自报数据、展示趋势 | DeskCare 只提供可选的粗颗粒度状态记录，不提供诊断、风险评分或疗效建议 |

休息软件 Workrave 官方介绍了基于键鼠活跃/空闲时间的微休息、较长休息、每日上限，以及按日、周、月查看电脑使用时长和休息反馈的统计。因此，“记录电脑使用时间”“提醒休息”“统计提醒反馈”都不是 DeskCare 独有的单项功能。[Workrave 休息机制](https://workrave.org/docs/breaks/)，[Workrave 使用统计](https://workrave.org/docs/windows/statistics/)

DeskCare 当前更值得验证的差别，是把用户确认的任务、自己选择的情境、可选的电脑使用概览、休息反馈和主动填写的简单状态放在同一个本地回顾流程里；任务完成仍由用户确认，不能由应用使用时间推断。公开资料对照不等同完整竞品功能审计，不能据此断言其它产品没有类似能力。

以上差异是产品定位，不表示 DeskCare 已经比这些产品更有效、更健康或更受欢迎。需要通过普通学生和上班族的可用性测试来验证。

## 后续迭代路线（按证据排序）

1. **先完成真实用户验收**：修复安装启动、托盘、授权、任务和报告流程的阻塞问题；请未参与开发的学生/上班族独立走查并记录卡点。未通过前，不扩大功能范围。
2. **降低首次使用门槛**：基于走查结果简化授权解释、任务添加、情境选择和休息反馈；语音输入应保留手动输入作为无需额外模型/账号的路径。
3. **完善发布体验**：评估代码签名、安装包/更新方式、干净 Windows 用户目录兼容性，以及语音模型如何安全、清楚地提供；明确费用、网络和数据去向后再决定云服务。
4. **再验证整合价值**：通过访谈或小规模可用性测试，确认用户是否真的需要“任务 + 使用节奏 + 自报状态”的合并回顾，以及是否觉得数据授权清晰。根据证据保留、调整或删除低价值模块。

以上是建议顺序，不表示相关发布能力或用户研究已经完成。M18 当前仍需真实 Windows 与非开发者验收。

## 当前架构

```text
PySide6 桌面界面
  ├─ 今日任务 ── 导入器草稿 ── 用户预览/确认 ── SQLite
  ├─ 活动统计 ── 授权控制 ── Windows provider ── 每日聚合 SQLite
  ├─ 温和提醒 ── 规则策略 ── 最小依据留痕 ── 用户反馈
  ├─ 状态打卡 ── 独立授权 ── 用户主动填写 ── SQLite
  └─ 今日/每周报告 ── 本地事实模板 ── 用户主动导出
       ├─ 可选本机 AI 润色（单独启用）
       └─ 可选联网任务整理（逐次预览和确认）
```

- Windows 活动采样默认关闭；暂停后立即停止读取。应用名称统计另行授权。
- 只保存按日期聚合后的时长，不保存键盘内容、窗口标题或浏览页面。
- 任务文件先解析为草稿；用户确认后才成为任务。语音识别结果同样先显示草稿。
- 提醒依据只记录复核规则所需的最少字段，不记录任务标题或应用名。
- 模拟模式使用独立数据库，不与日常活动历史混合；模拟数字必须明确标识。
- 所有健康相关文案以个人主动输入和生活建议为边界，不把关联描述为因果或医学判断。

## 尚未承诺的能力

- 真正 Live2D 形象、云端语音服务、自动任务识别/完成、云同步、医学诊断或疗效预测均未实现。
- 没有默认云端 AI 服务或费用承担方案；联网能力需要用户主动配置并在每次发送前确认。
- Windows 签名安装程序、自动更新和多用户账户隔离还需单独制定发布计划。
