# 01｜DeskCare 产品项目书（PRD）

**状态**：持续迭代中的产品要求；阶段实现与验收见 `PROGRESS.md`｜**首发平台**：Windows 10/11｜**目标群体**：大学生、开发者、电脑办公人群。

## 1. 产品主张

**DeskCare = 电脑使用感知 + 今日任务 + 自报状态与回顾**，通过统一的可解释策略关联，而非三个工具的简单堆叠。

一句话价值：让电脑了解你**主动提供的今日安排**、有限的使用行为线索和**自己填写的状态反馈**，在合适时机给出柔性休息提示，帮你看清时间花在哪里、任务推进到哪里、该怎样调整习惯。

**不卖什么**：不是医生、数字疗法、疲劳检测器、生产力打分器或全天候行为监视器。健康建议只是一般性用电脑休息支持。

## 2. 目标用户和核心场景

- **第一位种子用户**：Windows 笔记本大学生；打开 VS Code / 浏览器完成作业，任务、活动时间和休息被分散在多个 App。
- **第二位种子用户**：远程知识工作者；长期使用电脑、存在会议/深度工作、希望少被提醒打扰。
- **适合的第一批测试者**：愿意自愿安装试用的同学；不采集任何参与者的原始个人内容，测试展示使用虚构数据。

### 2.1 用户问题与应答方式

| 真实任务 | 现状问题 | DeskCare 应该做到 | 失败表现 |
|---|---|---|---|
| “今天要做什么” | 备忘录与正在用的电脑脱节 | 导入/编辑/核对今日任务 | 未确认的 AI 推断直接入库 |
| “我用了电脑多久” | 工作中不关注时间 | 展示活动时长估计、应用类别汇总 | 将没有键鼠输入误算为休息或睡眠 |
| “什么时候休息” | 固定时间提醒干扰工作 | 结合任务时限、静默模式、活动状态与反馈择机提示 | 任务临近截止仍全屏强制打断 |
| “这一周过得怎么样” | 信息散在任务、软件与主观记录中 | 按事实汇总：时长、任务、休息、状态与未知 | AI 虚构完成度、疲劳改善、因果关系 |

## 3. 核心用户旅程（首版完整闭环）

1. 安装后看到**隐私说明**，监测默认关闭；选择“开启使用统计”才收集有限活动信息。健康打卡另外开关。
2. 用户主动上传 `TXT / MD / CSV / XLSX` 今日清单或手工添加任务；导入后显示**候选任务预览**，可编辑标题、截止时间、预计时长，点击确认才写入。PDF/OCR 暂不做。
3. 主面板显示任务列表、当前监测状态、今日类别使用时长与最近的柔性休息建议。用户可手动设置“正在专注/上课/会议/阅读”模式。
4. 活动线索与用户确认的任务信息进入策略引擎。如果达到休息建议阈值且不处于静默场景，选择自然间隙用**不抢焦点**的方式提示；用户可以立即休息、稍后提醒、跳过或标记时机不合适。
5. 用户自己勾选任务是否完成。每日可选快速打卡：如“今天用眼感受：无明显不适 / 有些不适 / 不想记录”，**不进行医学诊断**。
6. 生成本地日报；积累多天后生成周报，附事实依据、未知数据及建议，所有建议可关闭。不要求使用在线大模型。

### 3.1 对比场景：联动而非堆叠

- 只用传统提醒器：连续工作 40 分钟，立即提示。
- DeskCare：连续活动 40 分钟，且用户手动开启“会议模式”→暂不打断；会议模式结束 + 存在自然切换迹象→柔性提醒；用户选择“此刻不合适”→在受限范围内降低同类情境的提醒频率。
- 注意：程序类别（例如 VS Code）**不能证明用户正在完成某个清单任务**。系统只显示“可能与某任务相关”，要求用户确认，不能自动完成任务。

## 4. 页面信息架构

**四个主页面 + 托盘 + 提醒卡片**：

1. **今日**：今日任务（导入/手工、状态修改）、剩余截止时间、快捷专注、当前建议；不自动排挤睡眠或课程安排。
2. **使用统计**：今天按**应用类别**的活动分钟、连续使用估算、暂停/空闲提示、手动场景模式；具体应用名统计作为授权后选项。
3. **状态与报告**：可选状态打卡、日报、周报、数据完整性和证据来源；未授权健康数据时仍可用。
4. **设置与隐私**：监测/应用名/健康记录/可选 AI 的各项独立开关、工作/休息阈值、静默时段、数据导出和清除、退出。

**提醒卡片**：显示“建议稍微休息一下”、原因（如“估算连续活跃 42 分钟，最近出现应用切换”）、`现在休息` / `10 分钟后` / `跳过` / `时机不合适`。不覆盖全屏、不会锁住操作。

## 5. MVP 功能验收（P0）

| ID | 交付能力 | 用户可验证的结果 |
|---|---|---|
| P0-01 | 明确许可门控 | 首次监测、健康打卡默认关闭；随时停止 |
| P0-02 | Windows 托盘应用 | 主窗口关闭后托盘可访问；退出真正结束 |
| P0-03 | 活动统计 | 前台类别、活跃/空闲估计、每日聚合；可查看采样受限原因 |
| P0-04 | 任务导入 | `txt/md/csv` → 草稿 → 用户确认 → 今日任务；格式错误有清晰反馈 |
| P0-05 | 今日任务编辑 | 添加、完成、撤销、删除，不自动猜测完成 |
| P0-06 | 联动决策 | 活动 + 用户静默模式 + 截止时间 + 提醒反馈；展示 reason codes |
| P0-07 | 低打扰提醒 | 可跳过/推迟，不抢占输入焦点，暂停后不再提示 |
| P0-08 | 状态打卡 | 明确独立授权，输入可跳过，可删除，不推断诊断 |
| P0-09 | 日报/周报 | 只基于持久化事实；缺数据要注明；至少支持模板报告 |
| P0-10 | 可测性与打包 | fake 数据演示、pytest、Windows 本机试验、onedir 打包 |

**次优先级（P1）**：xlsx 导入；本地 LLM（如用户已装本地推理服务）解析模糊任务/润色报告；显式同意后按具体应用名统计；匿名 A/B 对照；可解释反馈权重调整。

**AI 参赛演示要求**：规则引擎本身不是机器学习模型。若项目以“AI 应用”提交，除可独立运行的离线核心功能外，还需要至少实现并**实际演示**一项模型推理：推荐先做用户自选清单的 LLM 候选任务提取 + 人工确认，其次做 FactSheet 的受约束语言总结。优先本地模型；没有模型运行时，不得虚称已接入 AI。

**暂不做（P2）**：手机端、云同步、视频摄像头姿势识别、应用强制锁、浏览器插件、全屏截屏、文档后台读取、AI 从应用猜测你完成哪项任务、精神健康诊断/疾病诊断、自动给医生建议。

## 6. 商业模式与差异化（都是假设，须验证）

- **竞品对照**：Stretchly / Workrave（休息提醒）、ActivityWatch / RescueTime（使用统计）、Notion / 待办 App（任务）、LookAway / Rize（情境识别）。以上不同程度覆盖单项能力。
- **差异化待验证**：已确认的待办时间约束进入休息策略；“为什么提醒/为什么暂缓”可解释；使用行为 + 任务 + 自报状态的统一事实性总结；本地优先与分项许可。
- **获客路径假设**：先从大学生 Windows 用户测试，降低安装门槛；之后探索程序员与桌面办公人员。
- **收费路径假设**：基础免费，后期可考虑高级历史分析/个性化策略的一次性买断或增值版。**不预设用户愿意付费**，不靠制造焦虑促转化。

## 7. 北极星与防刷指标

- 核心：**用户认为恰当且愿意接受的休息提示占比**，同时跟踪用户确认的休息次数。
- 质量护栏：打扰评分、提醒次数、推迟/跳过比、首日可用性、次周留存（如果具备数据）；休息建议触达机会覆盖率防止“从不提示”作弊。
- 产品联动检验：用户导入任务与未导入任务时，体验是否有区别；“结合任务”对用户是否有实际感知。
- 数据表述：活动分钟不等于屏幕亮屏、实际工作时间或学习质量；用户点击开始休息不等于生理上完成休息。

## 8. 完成标准

比赛前目标：一名用户能从启动到导入任务、生成提醒、记录反馈、完成打卡、查看有依据的日报，全流程体验无致命中断。周报可通过**明确标注为模拟的跨日演示数据**展示。避免因为追求海量功能影响真实稳定性。

## UI10 已确认增量：本人记录与行动回顾

用户于 2026-10-20 确认按健康助手方案分阶段推进。第一阶段新增独立授权、默认关闭的多次不适事件记录，用户确认后加入普通任务、自愿后续补记及本机回顾／选定导出。每日粗粒度打卡继续独立；不根据活动或任务推断症状／病因／改善，不自动移动原计划，不新增医疗建议。详细验收和删除关系见 `UI10_不适记录与行动回顾.md`。

医院检验单辅助阅读仍需下一阶段明确资料／模型／上传范围和专业审核，当前不属于已实现能力。AI 任务解析与现有报告通道不接收新增不适数据。

## UI11 已确认增量：提醒安排建议

2026-10-20 用户要求先升级提醒，再做检验单辅助阅读。旧自动加 5 分钟改为按反馈建议复核间隔，需用户确认才改。可主动选择一项当前任务、可选本次粗粒度感受，与当前模式、计时估计、反馈计数形成最小快照，供本机／联网 AI 在受限策略中选择；独立授权、逐次预览确认，不后台调用。AI 不识别屏幕或推断正在做哪项任务、不读取健康历史、不直接控制提醒。保留离线核心能力，真实模型适用性和少打扰效果仍待检验，见 `UI11_提醒安排与AI建议.md`。

## UI12 用户实测修正与自然语言入口

修复当前 1 分钟把候选限制为 5 分钟的问题，AI 常规建议使用 20–60 分钟产品候选（非医学标准），不把两小时任务总耗时等同提醒间隔；配置变更统一同步，发送前普通文字替代 JSON。右上角助手将用户主动消息规划为受限工具，读取结果只本机显示；改间隔／情境、添加任务须确认，不能执行任意电脑或健康操作。助手独立默认关闭许可，不上传对话历史、任务库或工具结果；范围和局限见 `UI12_助手与提醒修复.md`。检验单辅助阅读仍后排。
> UI13 增量（2026-10-20）：新增独立检验单辅助阅读，范围限六项常见血常规；本机提取、人工逐项核对、原报告范围对照与一般知识说明。可选 AI 仅选阅读重点及就诊问题，逐次确认，不诊疗。助手新增小时表达解析；见 `UI13_检验单辅助阅读.md`。历次定义与此增量冲突时，以此增量为准。
