# M3 验收记录

## 范围

M3 实现“任务 × 有限活动 × 用户情境”的低打扰休息提醒。提醒只由本地规则生成，不弹出模态窗口、不抢焦点、不读取键盘内容，也不把活动时长解释为医学或健康结论。

## 已实现

- `BreakPolicy` 作为纯函数式决策层，明确处理监测授权、暂停、未知观测、空闲证据、冷却、安静情境、专注截止时间、自然空档和软延迟上限。
- “今日”页面增加普通工作、专注模式、会议中、阅读中、安静时段等用户主动选择的情境输入。
- 采样定时器在完成受控采样后驱动策略评估；只把有限的最新样本保留在内存，不保存原始窗口标题、URL、键盘内容或截图。
- 提醒以页面内联卡片展示，不改变当前焦点；支持“现在休息”“10 分钟后”“跳过”“时机不合适”。
- 用户反馈写入本地 `reminder_events`，用于冷却和后续事实回顾；不保存提醒卡片之外的敏感上下文。
- 已完成任务只在用户主动修改状态后产生“可能存在自然空档”的策略信号，未确认任务不会进入提醒依据。
- 关闭或暂停活动监测时，提醒立即隐藏并停止依赖活动样本。
- SQLite v3 增量迁移保留 M1 活动聚合、M2 任务和授权状态。

## 自动化证据

在项目虚拟环境中执行：

```powershell
python -m compileall -q deskcare tests
python -m pytest -q
python -m pip check
```

M3 覆盖纯策略边界、任务截止时间约束、自然空档、延迟上限、反馈冷却、提醒事件持久化以及关闭/暂停硬门控。当前 M3 回归为 **33 passed**，依赖检查为 **No broken requirements found.**

入口冒烟使用 `QT_QPA_PLATFORM=offscreen` 创建 QApplication，并验证四页窗口、提醒协调器和定时采样回调可以装配。真实 Windows 托盘、DPI 和 Win32 provider 仍需按人工清单验收。

## 隐私与伦理检查

- 默认活动监测仍关闭；M3 不改变首次启动授权。
- 提醒文案使用“可以考虑”“可能”等非诊断表达，不宣称疲劳、疾病或工作质量结论。
- 不接入 LLM，不联网，不上传活动、任务或健康数据。
- 不把提醒策略生成的 `SOFT_NOTIFY` 当作用户已经休息或健康改善的事实。
