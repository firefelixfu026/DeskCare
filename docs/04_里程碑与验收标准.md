# 04｜开发里程碑、任务拆分与验收标准

目标是**每一阶段都有可运行的软件**，优先交付端到端的小闭环，而不是堆砌华丽 UI。

## M0｜可运行骨架（第一轮交给 Codex，只做这一轮）

**范围**：`pyproject.toml` / `src/deskcare` / `python -m deskcare`；PySide6 主窗口四页（今日、使用、状态与报告、设置）；系统托盘，打开/暂停/退出；首次进入监测显示默认关闭；FakeProvider 驱动的示例卡；README；最基础 pytest。

**验收**：
- `python -m deskcare` 能打开、切页和退出；关闭主窗口后托盘可重新打开；缺少系统托盘时要明确降级，不允许无法退出。
- 首次进入不读取 Windows 活动，不访问用户文件，不调用网络。假数据有明确的“演示数据”标签。
- 关闭或暂停后 UI 状态正确；M0 可先用内存态；各页不过分复杂。
- `pytest -q` 能运行至少 3 个基础测试（配置默认、FakeProvider、初始未授权状态）。
- 在非 Windows 环境，UI/托盘可能需 skip；不造 Windows 验收结果。

**不做**：真实 Win32 监测、AI 调用、导入、报告、完整数据库功能。

## M1｜活动采集与类别统计

**范围**：Win32 Provider 采集键鼠空闲秒数和可选前台应用类别；用户主动开启/暂停采集；连续时长估算；SQLite `consents`, `usage_daily` 与增量迁移；使用统计页展示。

**验收**：监测关闭不调用 Provider；活跃/空闲累计合理；采样异常可见；睡眠唤醒大间隔不计为一直工作；跨天分桶；默认无应用名明细。FakeProvider 覆盖单测；**Windows 实机**监测切换与锁屏验证。

## M2｜今日任务与文件导入

**范围**：手工增删改任务；系统文件选择器选 `txt/md/csv`；预览任务草稿并允许编辑/取消；用户确认写入 `tasks`；今日页显示期限、状态；禁止后台读取文件。

**验收**：测试 UTF-8 中文、BOM、空文件、错误列名、损坏 CSV、模糊时间、重复任务、超大文件、未确认不得入库。即使禁用 AI/监测，任务管理仍可用。

## M3｜任务联动与柔性提醒（核心创新演示）

**范围**：可单测纯函数 `BreakPolicy`；读取**已确认**截止任务、使用状态、用户模式、提醒历史；非阻断提醒卡；休息/10分钟后/跳过/时机不合适反馈；清晰的中文原因；提醒去重、冷却。

**验收**：至少 12 个决策场景测试全部通过；演示“相同连续时间，会议/截止临近/自然间隙产生不同决策”；关闭监测立即停止；任何场景可退出、跳过；不触发窗口抢焦点。

## M4｜自主健康打卡与真实报告

**范围**：状态记录默认关闭、单独开启和删除；自报简短舒适度；从 `usage_daily`、`tasks`、`reminder_events`、可选 `wellness_entries` 聚合 FactSheet；模板日报/周报；本地可查看或导出 TXT/Markdown。

**验收**：没有数据只说明没有数据；只记录一天不生成趋势；无法从前台程序推出具体任务是否完成；没有健康授权不输出健康状态分析；可核对报告中的所有数字，列出时间范围和数据覆盖情况。

## M5｜稳定性、实测和可交付程序

**范围**：修复采样与权限异常；Windows 系统托盘与 DPI 检查；PyInstaller onedir；本地清空数据；README 安装卸载说明；1 分钟快速演示流程；性能/隐私实测；与固定间隔提醒基线的可复现实验。

**验收**：在 Windows 10/11 中启动、不依赖开发 IDE；退出后后台进程不继续采集；离线可用；同一测试集上固定基线与任务感知策略的对照报告诚实描述测试条件（不预设赢家）。

## M6｜真实 AI 能力（建议在参赛演示前完成最小项；个性化学习可延期）

- **参赛最小真实 AI 功能**：接入可选择的本地模型，仅处理用户选定的清单文本，生成可编辑的 `TaskDraft`，要求 JSON 结构化校验和人工确认；没有模型时保持离线规则兜底。
- AI 清单解析采用草稿预览和人工确认；AI 报告叙述必须校验事实数字。
- 在足够真实反馈且用户授权的条件下调整软提醒参数，提供可视化解释、一键重置；没有数据不能虚构“模型已经学习”。
- 无论是否完成 M6，M0–M5 都必须独立可运行；但**未真正运行模型时不能向评委称其为已实现的 AI 推理产品**。

## 优先级与时间预算

### 后续扩展里程碑（M7–M9）

- M7：具体应用明细独立授权和轻柔活动提示；关闭应用明细授权立即清除应用级聚合。
- M8 历史范围：可隐藏悬浮伙伴、手动任务/情境操作和本地语音草稿。UI2 已按用户要求移除语音部分，保留任务与情境交互。
- M9：默认关闭的可选云端任务解析；API Key 仅存 Windows Credential Manager；每次请求逐次预览确认。不得上传活动、应用统计、BodyLog 或报告。
- 自动测试只能证明模拟传输与门控逻辑；Windows Credential Manager、实际服务商/API Key 和网络链路需按各阶段人工清单验收。

| 优先级 | 必须保证 | 可砍掉 |
|---|---|---|
| P0 | 本地活动估计 + 任务确认 + 情境休息 + 报告事实 + 授权门控 | 花哨动画、复杂图表 |
| P1 | 简单状态打卡与摘要、导出、真实 Windows 打包 | xlsx、窗口细节美化 |
| P2 | 本地大模型、自动个性化学习、具体应用名统计 | 多平台、应用锁、云同步 |

**建议时间安排（以实际赛事截止通知为准）**：先完成 M0/M1，接着 M2/M3 联动演示，再做 M4。若以 AI 产品参加比赛，尽量在最终 M5 打包前完成 M6 的**最小真实模型链路**；更复杂的个性化训练可以赛后进行。

## 必备自动化测试（最低清单）

- 首次未授权时不触发采样；暂停后不再调 Provider。
- 同一个工作会话在不同情境下输出不同可解释 reason_codes。
- CSV/Markdown 导入仅给草稿；用户取消后数据库任务数不变。
- 任务完成必须由用户动作触发；不能依据应用使用记录完成任务。
- 监测时间 0 与监测未开启不同；显示“无数据”而非“0 分钟”。
- 删除健康打卡后报告不包含旧打卡内容。
- 任务/活动/提醒统计数字与原始**结构化记录**相符。
- 多日缺失时周报不发趋势判断；跨日与休眠间隔正确截断。
- 数据库迁移保留用户老数据；UI 层不访问系统采样细节。

## 参赛演示脚本（60–90 秒）

1. 展示“上传今日任务清单”，预览、修正模糊时间并确认。
2. 进入使用统计，明确指出是估计活跃分钟、不是监控浏览内容。
3. 切换到模拟会议模式，展示达到阈值也不会干扰；再模拟任务完成后的自然间隙，触发轻量提醒并显示原因。
4. 选择“稍后提醒”或“时机不合适”，展示反馈进入历史。
5. 完成可选状态打卡，打开来自样例数据的日报/周报，突出事实、缺失说明与可追溯性。
6. 最后清晰展示“暂停监测”和“清除数据”，讲明隐私价值与产品边界。

**所有模拟输入必须明确标记为演示数据**，不能伪装成真人用户量、真实连续一周数据或经过医学验证的产品效果。

## UI10｜已确认的第一阶段健康记录闭环

实现“主动记录 → 用户确认行动 → 自愿补记与回顾”。最低验证：默认独立关闭；取消无写入；同日多次不覆盖每日打卡；无补记不推断改善；行动未确认不入库；关联与任务原子写入；删除事件／任务互不误删；撤回清除并刷新页面；全部清除及升级备份覆盖；新增健康文本不进入原 AI 通道；选定导出无其他事件或活动轨迹；不同窗口高度分页。无模型、无监测时该流程仍可用。测试和渲染不替代 Windows 原生验收，也不证明医学有效性。

## UI11｜用户确认的提醒复核与 AI 策略建议

先完成本阶段，再做医院检验单辅助阅读。最低验证：反馈只建议、不自动修改；分情境阈值／间隔上限／处理后不反复提示；当前任务由用户选择而非应用推断；感受默认不提供且不读健康历史；旧任务 AI 许可不能授权新快照；打开／预览零网络，逐次确认后才请求；准确正文与实际发送一致；无效／超长／截断／越界／虚构依据拒绝；授权、任务、模式、间隔、暂停、活动可用性和模型配置变更丢弃旧结果；应用间隔须确认；离线与模型失败不影响原提醒。原生 Windows 焦点／全屏／多屏、真实模型输出质量与真实使用对照另行验收，不以模拟传输证明真实推理。
